# C++ の書き方

AGENTS.md から「C++ を書く・直す前に読む」として指されているファイル。
整形（インデント・括弧の位置など）は `.editorconfig`・`.clang-format` に任せ、ここには機械で決められない事だけを書く。

## 名前
- 既存の変数名・関数名が、これから作る物と区別しにくいなら、既存の方を変えてよい。
- namespace に関数を作る前に、他のクラスの public に同じ働きの関数が無いか探す（同じコードを増やさない）。

## include の順番
グループの間は1行空ける。

0. 自身の .h（cpp のみ）
1. 標準ライブラリ（.h なし）
2. 標準ライブラリ（.h あり）
3. 外部ライブラリ（.h なし）
4. 外部ライブラリ（.h あり）
5. 自作ライブラリ（.h なし）
6. 自作ライブラリ（.h あり）

```cpp
#include "Camera.h"

#include <vector>
#include <iostream>

#include <stdio.h>

#include <externals/external.h>

#include "httengine.h"
```

## コメント
いつ読んでも分かるように、しっかり付ける。見出しは4段。

1. 大見出し（クラス・関数の実装のまとまり。後ろに2行空ける）
   ```cpp
   //=============================================================================
   // 初期化・終了
   //=============================================================================
   ```
2. 中見出し（1つの関数など。前後に1行空ける）`// ===== 初期化 =====`
3. 小見出し（関数・クラスの中の区切り）`// --- 読み込み ---`
4. 説明（変数の右など）`// 〇〇`

```cpp
//=============================================================================
// 初期化・終了
//=============================================================================
// ===== 初期化 =====
void SoundDecoder::Initialize() {
	// Media Foundation初期化（MP3等のデコードに使う）
	const HRESULT hr = MFStartup(MF_VERSION);
	HTT_ASSERT_MSG(SUCCEEDED(hr), "MFStartup失敗");
}

// ===== 終了 =====
void SoundDecoder::Finalize() {
	MFShutdown();
}
```

- あまり使われない STL を使うときは、その STL の説明をコメントに書く。
- 複雑な処理には、何をしているかの説明を書く。

## ポインタとメモリ
- `new` / `delete` を直接書かない。持ち主が1人なら `std::unique_ptr`、共有するなら `std::shared_ptr`、持ち主でない参照は `std::weak_ptr` か生ポインタ（その場で使うだけ）。
- ゲーム側は、エンジンの中の物を生ポインタでフレームをまたいで持たない（Handle・EntityId を使う）。理由は `Docs/ARCHITECTURE.md` の基本設計原則 1。

## 標準ライブラリを使う
| こう書いていたら | こうする |
|---|---|
| 動的配列の `new[]` | `std::vector` |
| C 配列 | `std::array` |
| `char` の文字列 | `std::string`（`char` は使わない） |
| `rand` | `std::mt19937` など `<random>` |
| 全要素を回す添字の for | 範囲 for |
| 自分で書いた定数（`3.14159f` など） | `std::numbers::pi_v<float>` など STL の物 |

- `std::max` / `std::min` は `Windows.h` のマクロとぶつかる。`#define NOMINMAX` を使うか、使わない書き方にする。

## 分岐
- 値が 3 つ以上ある enum で分けるときは `switch` を使う（`default` は書いてよい）。1つの値だけ聞くなら `if (x == A)` のままでよい。

## ImGui
- 数値の入力は Slider ではなく Drag を使う（細かい値を打ち込めるように）。

## 見直すこと
- 同じコードのコピペが増えていないか。
- メモリの持ち主がはっきりしているか（unique_ptr・shared_ptr・weak_ptr の使い分け）。
- 1つのフォルダのファイルが 15 を超えたら、フォルダ分けを考える。
