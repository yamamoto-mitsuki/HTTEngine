# ブランチ・コミット・vcxproj の扱い

AGENTS.md から「ブランチを切る・コミットする・vcxproj がぶつかったとき」に読むと指されているファイル。

## ブランチ
| ブランチ | 使い方 |
|---|---|
| `master` | 動く状態だけを置く。`develop` を早送り（fast-forward）でそろえる |
| `develop` | 作業を集める所。ゲームのサブモジュールはここを追う |
| `feature/〜` | 1つの作業ごとに `develop` から切る。名前は英語の PascalCase（例: `feature/CharacterController`）。入れ終わったら消す |

## コミット
- メッセージは日本語で、何をしたかを1行目に書く（例:「Trail に持ち主が消えた後の消え方を足す」）。
- 設計の md とコードを分けるときは、md のコミットを先にする。
- ビルドが通らない状態でコミットしない。`generated/` や `*.user` は入れない（`.gitignore` 済み）。

## vcxproj・filters がぶつかったとき
- `HTTEngine.vcxproj` と `.vcxproj.filters` の `<ClCompile>` / `<ClInclude>` の行は、両方の変更を残す（どちらかを消すと、そのファイルがビルドから外れる）。
- 解いた後、同じファイルが2行になっていないか、filters の `<Filter>` が vcxproj のファイルと合っているかを見る。
- Visual Studio で開き直してビルドが通ることを確かめる。

## シーン・Prefab の JSON がぶつかったとき
- Entity の番号はでたらめな 64 ビットなので、別々に足した Entity はぶつからない。ぶつかるのは同じ Entity を2人が直したときだけ。
- 手で直したら、エディタで開いて読めることを確かめる。

## ゲーム（サブモジュールで使う側）との関係
- エンジンの変更はこのリポジトリでコミット・push してから、ゲーム側でサブモジュールを上げる。
- ゲームのリポジトリの中の `HTTEngine/` で直接直したときも、コミットと push はこのリポジトリに対して行う。
